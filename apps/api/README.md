# Rugby AU API

Run commands from the repository root with `pnpm --filter api <script>`.

The development script pipes API logs through `pino-pretty` for readable, colored
output. Production logs from `pnpm --filter api start` remain JSON.

The API loads `apps/api/.env` at startup through `dotenv` when run with the
workspace scripts. Access values with `process.env`; existing environment
variables take precedence. The `.env` file is ignored by Git.

Set `MONGODB_URI` in `apps/api/.env` (see `.env.example`). The server connects
through Mongoose before accepting requests, using the same default connection as
the Typegoose models. Startup fails if the URI is missing or MongoDB cannot be
reached within five seconds. Database errors are logged, and `SIGINT`/`SIGTERM`
close the HTTP server and database connection. Collection and index creation stay
in migrations; starting the API does not run migrations automatically.

`buildApp()` registers the MongoDB startup and shutdown hooks in `src/app.ts`.
The connection opens when Fastify becomes ready.

| Script         | Purpose                                                                    |
| -------------- | -------------------------------------------------------------------------- |
| `dev`          | Run the API on port 3001 and restart when source files change.             |
| `build`        | Compile production files into `dist/` and rewrite aliases for Node.js ESM. |
| `start`        | Run the compiled API after building.                                       |
| `typecheck`    | Check source files and TypeScript configuration files.                     |
| `lint`         | Check files with type-aware ESLint rules.                                  |
| `lint:fix`     | Apply available ESLint fixes.                                              |
| `format`       | Format API files with Prettier.                                            |
| `format:check` | Check formatting without changing files.                                   |
| `check`        | Run type checking, linting, formatting checks and a production build.      |

## TypeScript configurations

- `tsconfig.json` contains shared compiler options and editor settings.
- `tsconfig.build.json` extends the base and emits production source files only.
- `tsconfig.eslint.json` extends the base and includes TypeScript files for type checking and ESLint.

Generated output and dependencies are excluded from checks.

## Database migrations and initial data

Set `MONGODB_URI` in `apps/api/.env` to the database you want to migrate, then run
from the repository root:

```bash
pnpm --filter api migrate:status
pnpm --filter api migrate:up
```

This creates the collections, renames the site's `slug` field to `siteKey` and
updates its unique index, then seeds `Rugby AU` (`rugby-au`) and `Wallabies`
(`wallabies`) sites with IDs generated by `randomUUID()`. Rugby AU uses the default
theme defined by the site model; Wallabies uses a gold primary color (`#FFCD00`).
The `siteKey` is a unique, lowercase, hyphen-separated identifier for a site.
The seed supplies timestamps and theme fields explicitly because native MongoDB
writes do not apply model defaults. It leaves any existing site with either key
unchanged, and rerunning it does not create duplicates.

`pnpm --filter api migrate:down` rolls back the most recently applied migration.
For the site seed, this removes sites with `siteKey` values `rugby-au` or
`wallabies`, including any pre-existing sites with those keys. Rolling back the
field rename restores `slug` and its unique index. Pages are not seeded.

Keep required initial data in migrations so each database receives it once through
the migration changelog. Optional development fixtures should use a separate seed
script so they are not automatically inserted into production databases.

## Imports

Use extensionless `@/` imports to reference `src/`, such as `@/app`.
The build uses `tsc-alias` to turn aliases into relative imports with `.js` extensions.
